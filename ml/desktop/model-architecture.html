Board context (4)

  • min dist to tower / 10nearest existing tower
  • 3×3 density / 5towers in adjacent cells
  • dist to same-type / 10nearest tower of same type
  • dist to path / 20nearest creep-path cell (plains: row 13)

Game state (5)

  • wave / 20current wave
  • tower count / 100towers already placed
  • gold / 1000current gold — can you afford to keep building?
  • tower cost / 500cost of the tower being placed
  • lives / 100current lives — risk tolerance
Are the region one-hots redundant? Yes, strictly — the network could infer "left third" from col / 36. They were added as an explicit hint so region boundaries are sharp instead of something the first layer has to discover. Whether they actually help is an empirical question: run python ml/desktop/ablate.py --feature region and see if val loss moves. If it doesn't, they're removable.

How It Works

For each candidate cell, the model scores how likely Alex would place a tower there given the current board state.

Training: positive examples are cells where Alex (or a winning bot) actually placed a tower. Negative examples are 5 random other cells from the same board state. The model learns to distinguish good placements from random ones.

Inference: StrategistBrain evaluates all candidate cells through the model, picks the highest-scoring cell above a threshold (0.3). If no cell scores high enough, it falls back to hand-coded logic.

What's still missing: the model doesn't see what creeps are coming next, when in the wave cycle the decision happens, or the send economy. Gold, lives, tower cost and path distance were added 2026-11-06 — gold/lives are near-constant in legacy training data (captures don't record them yet), so they only become informative as new captures include them.

Per-faction: each faction gets its own model because placement patterns are faction-specific (void gamblers cluster at entry, psionic probes interleave with mesmers, etc.). A single shared model would blur these patterns.

Training data: 897,947 examples in v5 — synthetic bot wins, expert replays (×10 weight), augmented expert (×3), procgen patterns (×2), directed search (×5).

Validation: ml/desktop/imitation_accuracy.py measures how often Alex's actual placement ranks in the model's top 1 / 3 / 5. ml/desktop/ablate.py measures which features matter by retraining with each one zeroed out.
